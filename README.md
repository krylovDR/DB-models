## Моделирующая программа различных типов РСХД
В данном проекте реализована моделирующая программа для экспериментальных алгоритмов взаимодействия с данными в реплицируемой системе хранения данных (РСХД). Использована метрика "Возраст информации" (Age of Information - AoI) для оценки эффективности работы систем. Далее приведена структура проекта, а также система допущений для каждой модели.

### Структура проекта
* core - главные классы с логикой работы каждого типа РСХД;
* graphics - мини-библиотека для построения графиков;
* simulation - классы, отвечающие за моделирование процесса работы РСХД;

### РСХД Dynamo-типа
#### Допущения модели
* Параметры модели:
    + **n** - количество узлов в системе (__n > 0__);
    + **w** - количество узлов в кворуме записи (__0 < w <= n__);
    + **r** - количество узлов в кворуме чтения (__0 < r <= n__);
    + **q** - вероятность успешной записи на узлы (__0 <= q <= 1__);

* Показатели модели:
    + **AoI** - средний возраст информации по запросу на чтение;
    + **versionAge** - время жизни процесса записи обновления (__в слотах__);
    + **timeStamp** - временная метка последнего обновления на узле;
    + **verProfit** - насколько успешных записей было больше, чем __w__ (__на основе этого параметра можно оценить оптимальность выбранных размеров кворумов__);

* Общее описание работы системы:
    + Шкала времени:
        - Единицей времени является слот;
        - Время разделяется последовательно на слоты одинакового размера;
        - События инициализации обновления, записи и чтения привязаны к слотам;
    + Процесс записи:
        - Источник отправляет данные на **все** узлы, но ожидает только __w__ откликов с подтверждением записи из всех __n__ узлов системы (__ответившие входят в подмножество W - кворум записи__);
        - Успешная запись на узел описывается вероятностью __q__;
        - Попытка записи разыгрывается в начале каждого слота;
        - Запись считается успешной после получения не менее __w__ подтверждений от __n__ узлов (__то есть успешных записей на узлы может быть больше, чем w__);
        - Запись одного обновления может растягиваться на множество слотов;
        - После успешной записи сразу инициируется следующее обновление, а оставшиеся __n - (w + verProfit)__ операций записи отменяются;
        - Узлы, на которые обновление записалось в первую очередь, ждут (__бездействуют__), пока обновление не запишется на другие узлы;
    + Процесс чтения:
        - Чтение может происходить только один раз в конце слота;
        - Случайным образом выбираются __r__ узлов, с которых происходит чтение клиентом (__эти узлы входят в подмножество R - кворум чтения__);
        - Операция чтения считается успешной, если получит __r__ откликов от системы;
        - Из __r__ версий данных клиент выбирает самую свежую;
        - Чтение может происходить независимо от записи, поэтому последнее обновление можно получить до официального завершения записи такового;
    + Процесс устаревания данных (__по времени__):
        - Записываемый пакет данных содержит временную метку __timeStamp__, хранящую время когда записанное обновление было инициировано;
        - Предыдущая временная метка на узле перезаписывается новой;
        - Имеется момент времени __t__. Возраст информации, это __t - timeStamp__;

* Режимы работы:
    + Строгая согласованность:
        - Кворум записи __W__ и кворум чтения __R__ должны пересекаться хотя бы в одном узле (__w + r > n__);
        - Получение самой последней версии обновления операцией чтения гарантировано, так как хотя бы один узел из кворума записи будет в кворуме чтения;
    + Нестрогая согласованность:
        - Кворумы записи и чтения могут не пересекаться (__w + r <= n__);
        - Гарантий получения последнего обновления нет;
